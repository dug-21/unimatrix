# vnc-019 Acceptance Criteria Map

| AC-ID | Description | Verification Method | Verification Detail | Status |
|-------|-------------|---------------------|---------------------|--------|
| AC-01 | `context_graph(mode="subgraph", seed_ids=[N], edge_types=["Supports"], direction="both", max_depth=2)` returns a JSON object containing `nodes` (array), `edges` (array), and `truncated` (bool) | test | Integration test in infra-001 suite; `test_protocol.py` P-04 coverage | PENDING |
| AC-02 | Each entry in `nodes` is a full `EntryRecord` serialized as JSON with the same shape as entries returned by other `context_graph` modes | test | Integration test field-shape assertion on returned node objects | PENDING |
| AC-03 | Each entry in `edges` is an `EdgeRecord` with fields: `source_id` (u64), `target_id` (u64), `relation_type` (string), `direction` (always `"outgoing"`), `depth` (u8, 1-based hop from nearest seed), `metadata` (null or parsed JSON value) | test | Integration test field-shape and value assertion on returned edge objects | PENDING |
| AC-04 | Seed entries are present in `nodes` regardless of whether they are also BFS-discovered neighbors; a call with a single isolated seed (no matching edges) still returns the seed in `nodes` | test | Unit test with isolated seed node that has no edges of the requested type | PENDING |
| AC-05 | `max_nodes=200` hard cap applies including seeds; when BFS would exceed `max_nodes`, BFS terminates early and `truncated: true` is returned; a call with 201 seed IDs must return `truncated: true` with exactly 200 nodes | test | Integration test with seed list of 201 entries; assert `len(nodes)==200` and `truncated==true` | PENDING |
| AC-06 | `max_depth` defaults to 3 when absent; passing `max_depth=0` or `max_depth=11` produces a validation error indicating the allowed range `1..=10` | test | Unit tests for boundary values: max_depth=0 (error), max_depth=1 (ok), max_depth=10 (ok), max_depth=11 (error) | PENDING |
| AC-07 | `seed_ids` absent or empty produces a validation error with message: `"subgraph mode requires at least one entry ID in seed_ids"` | test | Unit test: call with `seed_ids=[]` and call with `seed_ids` absent; assert error message matches exactly | PENDING |
| AC-08 | Unknown `edge_type` string produces a validation error naming the unrecognized value and listing recognized type names; when `edge_types` absent or empty, traversal uses `all_non_supersedes_types()` (15 types, excludes Supersedes); `edge_types=["Supersedes"]` explicitly traverses supersession edges | test | Unit tests: (a) unknown type string → validation error with type name; (b) default traversal omits Supersedes; (c) explicit Supersedes accepted | PENDING |
| AC-09 | `resolve_supersessions=true`: deprecated nodes encountered during BFS are replaced by their terminal active successors before enqueuing; the deprecated node does NOT appear in `nodes`; the terminal node does | test | Integration test: graph with deprecated node B (superseded_by C) in traversal path from seed A; assert B absent from nodes, C present | PENDING |
| AC-10 | `resolve_supersessions=false` (default): deprecated nodes are included in `nodes` as-is; edges are returned as stored | test | Integration test on same graph as AC-09 with resolve_supersessions=false; assert B present in nodes | PENDING |
| AC-11 | Passing `seed_ids` to `chain`, `current`, or `neighbors` mode returns the existing `validate_no_unsupported_params` validation error; the forward-compat guard is preserved after the subgraph arm is added | test | Unit tests: `context_graph(mode="chain", seed_ids=[1])`, `mode="current"`, `mode="neighbors"` — each must return validation error | PENDING |
| AC-12 | When `direction="both"`, a single stored edge `A→B` appears exactly once in `edges`; the `direction` field on that `EdgeRecord` is always `"outgoing"` | test | Integration test: graph with edge A→B; call with seed=[A, B], direction="both"; assert `len(edges)==1` and `edges[0].direction=="outgoing"` | PENDING |
| AC-13 | Tool description text for subgraph mode in `tools.rs` includes: (a) in-memory BFS and tick-window staleness, (b) `depth_reached` and `truncated` semantics, (c) unknown seed ID behavior (empty result, not error), (d) `EdgeRecord.direction` always `"outgoing"` | manual | Code review of `tools.rs` description string confirming all four disclosure categories present | PENDING |
| AC-14 | An integration test in the infra-001 suite writes 5+ entries with typed edges, calls `context_graph(mode="subgraph", ...)`, and asserts the returned nodes and edges match the expected subgraph topology (node IDs, edge triples, depths) | test | Run infra-001 integration test suite; confirm new subgraph topology test passes in CI | PENDING |
| AC-15 | `depth_reached` in the response equals the actual maximum BFS depth traversed; when BFS terminates early due to the `max_nodes` cap, `depth_reached` reflects the depth at which truncation occurred; when no edges are traversed, `depth_reached=0` | test | Integration tests: (a) full traversal asserts correct depth; (b) truncated call asserts depth at truncation point; (c) isolated seed asserts depth_reached=0 | PENDING |
| AC-16 | Passing `max_depth` to `chain`, `current`, or `neighbors` mode produces a validation error with message: `"max_depth is not supported in {mode} mode — use subgraph mode"` | test | Unit tests: `context_graph(mode="chain", max_depth=2)`, `mode="current"`, `mode="neighbors"` — each must return validation error with exact message | PENDING |
| AC-17 | A call where all seed IDs are absent from the in-memory graph returns `{ nodes: [], edges: [], truncated: false, seed_ids: [...], depth_reached: 0 }`; no error is returned | test | Unit test: call with non-existent seed ID (e.g., u64::MAX); assert all five response fields match expected empty-result shape | PENDING |
| AC-18 | When `GRAPH_EDGES.metadata` is non-null for an edge in the result, the corresponding `EdgeRecord.metadata` is a parsed JSON value (not a raw string); when null, `EdgeRecord.metadata` is JSON `null` | test | Integration test: insert graph edge with non-null metadata JSON; call subgraph including that edge; assert `edges[i].metadata` is parsed JSON object (not null, not string) | PENDING |
| AC-19 | When BFS produces no edges (isolated seed or cold-start), the post-BFS metadata batch query is not issued | test | Unit test: call with isolated seed node (no edges); assert response is valid with empty edges; verify no SQL metadata query was issued (e.g., via mock or instrumentation confirming no OR-chain query fires) | PENDING |
