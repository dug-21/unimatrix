## ADR-009: Knowledge-That-Helped (#206-4) Is Response-Time Enrichment, Not a Durable Column

### Context
SCOPE In-scope item 5 / Open Q3: #206 item 4 asks to surface "the entries that contributed to this cycle" in the retrospective. The design-session call is whether this needs a durable column or is response-time enrichment only. ass-077 is explicit (RQ-2, RQ-4): the load-bearing persisted KPIs are ranks 1–4 from durable streams; lower-value, list-shaped, or response-only signals stay as enrichment and are NOT persisted (SR-07 warns that #206-4 durability confusion invites over-building). "Which specific entries helped" is a per-review list (entry IDs/titles), not a cross-cycle scalar baseline — it does not compare across cycles the way the rank-1/2/3 aggregates do.

### Decision
Surface knowledge-that-helped as **response-time enrichment only — no durable column**. At review, compute the contributing entries from the already-available query_log ∪ injection_log served-to-cycle data (the same source as the rank-3 `knowledge_reuse_served_count` count, ADR-004) and attach the entry list to the response `RetrospectiveReport` presentation, NOT to the stored `CycleReviewRecord`. The durable surface for knowledge reuse is the rank-3 COUNT (ADR-004); the per-entry list is the response-time detail behind that count. This keeps the leak gate clean (no new persisted field, no content read on the persist path) and avoids persisting a list-shaped, non-comparable signal. If a measured need for cross-cycle "which entries recur" ever arises, it is a separate feature with its own column decision — not assumed here.

### Consequences
Easier: no new column, no migration coupling, no over-build; the count is durable and comparable while the list stays a response detail; the structural leak gate and the single-writer discipline are untouched. Harder: the helped-entries list is recomputed each review (not memoized) — acceptable, it is cheap and reads the same durable source as the count; a future "recurring knowledge across cycles" analysis would need new persistence. Cross-refs: ass-077 RQ-2/RQ-4 (persist the scalar aggregates, keep lists as enrichment), #206 item 4, ADR-004 (the rank-3 count this details), SR-07 (over-building risk), SCOPE Open Q3.
