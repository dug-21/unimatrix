## ADR-006: compaction_reread Boundary Selection — Gate on the Earliest compacted_at Per Session

### Context
SCOPE Open Q2 / SR-11: a session may have 0..N `compaction_events` rows (multiple compactions). `compaction_reread` must define WHICH `compacted_at` boundary it gates PostToolUse reads against — earliest, latest, or per-boundary segments. An undefined choice yields inconsistent or double-counted re-reads (SR-11). The signal's meaning (ass-077): "after the cycle strained against a compaction boundary, how much did it have to re-read?" — a per-cycle strain indicator, not a per-event audit. crt-054's `compaction_events` has an index on `session_id` and stores `compacted_at` in Unix seconds; `high_water` is populated but reserved (crt-055 v1 does not use it).

This ADR owns the gate reckoning, so it also owns the **clock-unit hazard** the gate depends on. Verified in the codebase (2026-06-16): the PostToolUse read `ts` is **epoch MILLISECONDS** — `ObservationRecord.ts: u64` is documented "epoch millis" (`unimatrix-observe/src/types.rs:39`), persisted as column `observations.ts_millis: i64` (`unimatrix-store/src/observations.rs:16`). `compaction_events.compacted_at` is **Unix SECONDS** (SCOPE Surface A). A naive `ts > compacted_at` compares millis against seconds: a 13-digit millis value is ~1000× any plausible seconds boundary, so **every read counts** (the gate is always true) — or, if someone "fixed" it the other way, none do. This is a silent gate break, not a crash. The prior design assumed "seconds-vs-seconds" (§9) — that assumption was wrong and is corrected here. This is no longer an open question; it is a binding contract clause (Binding constraint 8).

### Decision
For v1, gate on the **earliest** `compacted_at` per session and count each re-read at most once. Rationale: the earliest boundary captures the full post-first-compaction re-read tax for the session (the most inclusive within-cycle "had to compact, then re-read" window); per-boundary segmentation would double-count a file re-read across successive boundaries and overstate the tax; latest-only would undercount by ignoring re-reads between the first and last compaction.

**Binding unit clause — canonical gate unit is Unix SECONDS (human decision, 2026-06-16).** Any timestamp entering the gate comparison is normalized to seconds *first*. The normalization site is the `compaction_reread` reckoning, at the point the PostToolUse read `ts` is loaded for the gate: convert the millis `ts` to seconds with integer floor division — `read_ts_secs = ts_millis / 1000` (the existing `session_metrics.rs:115` `duration_secs = (max_ts - min_ts) / 1000` convention; same direction, same flooring). The boundary `compacted_at` is already seconds and is NOT touched. The comparison is then `read_ts_secs > MIN(compacted_at)`. Normalize the read side, never the boundary, so the producer contract (`compacted_at` = seconds) is untouched and the fix stays entirely consumer-side. Concretely: `SELECT MIN(compacted_at) FROM compaction_events WHERE session_id = ?1`; a PostToolUse read whose `(ts_millis / 1000) > MIN(compacted_at)`, re-reading a file already read before that boundary in the same session, counts once toward `compaction_reread_count`. An integration test MUST assert the unit: feed a read at `compacted_at_secs × 1000 + 500` ms (i.e. 0.5 s after the boundary) and a read 0.5 s before, and assert exactly the after-read counts — this fails loudly if the `÷1000` is dropped (both would count) or mis-applied. `compaction_count` separately reports the full COUNT of boundaries (ADR-005), so multi-compaction sessions are still visible as a count even though the reread gate uses one boundary. Document this as a fixed reckoning detail; revisit per-boundary segmentation only on measured need. `high_water` stays reserved for a future precise byte-boundary gate (no v1 use).

### Consequences
Easier: a single, deterministic, non-double-counting rule; one `MIN()` per session; the strain signal stays interpretable; `compaction_count` preserves the multi-compaction fact separately; the unit hazard is now a named, tested invariant instead of a latent silent-break (a future agent cannot reintroduce the millis-vs-seconds bug without failing the integration test). Harder: the earliest-boundary choice slightly over-attributes if a session compacts very early then runs long (acceptable for a directional strain signal); the reckoning carries a mandatory `÷1000` normalization that must not be skipped or double-applied (guarded by the integration test); if a future precise per-boundary tax is needed it requires `high_water` and a new reckoning (deferred).
