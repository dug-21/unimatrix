## ADR-002: Single store_cycle_review() Writer, Four Success Returns, No Zero-Clobber

### Context
The new aggregate columns sit behind the same single `store_cycle_review()` writer (`cycle_review_index.rs:209`) as crt-047's curation-health columns. `context_cycle_review` has FOUR success-return points (#4750): memo-hit, purged-retain (force=true + stored record), cached/empty-attributed, and the full-pipeline format dispatch. The dominant risk (SR-01, High/High; lesson #5022) is the #750 silent-zero / empty-clobber class: a second writer, or a recompute that ignores the data-presence gate, re-introduces zero-clobber where a purged cycle's real columns get overwritten with zeros. #758 established the typed-staleness + data-presence gate + purged-retain logic crt-055 must coexist with (Constraint 2,3).

### Decision
Write the new columns ONLY via the one `store_cycle_review()` call in the full-pipeline block, gated on `result.is_ok()`. The other three returns DO NOT write the new columns: the memo-hit return serves the stored record (no recompute, no write); the purged-retain return retains stored bytes untouched and surfaces the "source purged, cannot recompute" advisory (never the old "use force=true" string); the force+purged stored-record return serves without clobber. Recompute of pre-v5 stale rows happens ONLY via #758's clear-memo-and-fall-through path: when schema is stale AND source data is present (`!attributed.is_empty()`), the handler clears the memo and falls through to the full pipeline, which routes through the same single writer — so empty-clobber is structurally impossible. NEVER add a second writer near the memo/`check_stored_review` site. Add the three #5022 regression assertions: (a) data-present stale row recomputes and writes; (b) purged stale row retains byte-identical; (c) force=true on a purged row does not clobber with zeros.

### Consequences
Easier: the highest-likelihood failure class (SR-01) is closed by construction — one write site, three no-write returns; the recompute auto-refreshes pre-v5 rows when honest data exists and never fabricates zeros when it does not. Harder: every new column must be threaded through the single INSERT (`:249`) and UPDATE (`:284`) bindings; the four-return discipline is non-obvious (specs say "the last step before return" as if one return — #4750).
