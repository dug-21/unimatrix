## ADR-001: crt-055 Owns SUMMARY_SCHEMA_VERSION 4→5 and the Single cycle_review_index v5 Migration

### Context
crt-055 adds all new per-cycle aggregate columns to `cycle_review_index` (rank 1–3 aggregates, dual reload, transcript fold). This changes `CycleReviewRecord` JSON round-trip fidelity, so memoized pre-v5 rows must be flagged stale. SCOPE fixes ownership: #758 (merged `7aca6c44`) owns `SUMMARY_SCHEMA_VERSION = 4`; crt-054 owns NEITHER `SUMMARY_SCHEMA_VERSION` NOR any `cycle_review_index` migration (crt-054 ADR-008 / #5032); crt-055 owns 5 and the single migration that adds every new column at once. Current state: `SUMMARY_SCHEMA_VERSION = 4` (`cycle_review_index.rs:49`), DB `CURRENT_SCHEMA_VERSION = 28` (`migration.rs:22`). Patterns: #4153 (a bump touches three paths + the pinned-version test), #4484 (cascade-file existence), crt-047 v23→v24 is the column+migration template (`migration.rs:926-1059`).

### Decision
crt-055 bumps `SUMMARY_SCHEMA_VERSION` 4→5 (`cycle_review_index.rs:49`) with a bump-policy note (the new aggregate columns change round-trip fidelity), so stale memoized rows are recomputed via #758's guarded-recompute path (ADR-002). One DB migration adds ALL crt-055 columns to `cycle_review_index` in a single `current_version < N` block via `ALTER TABLE ADD COLUMN`, each `pragma_table_info`-existence-guarded (SQLite has no `ADD COLUMN IF NOT EXISTS`), copying the crt-047 v23→v24 template: all pre-checks before any ALTER, all ALTERs + the version bump in the same transaction, `INTEGER NOT NULL DEFAULT 0` for every numeric column — including `context_reload_pct` (basis points 0–10000, ADR-005; no REAL column) — and TEXT `'{}'` for `signal_class_counts_json`. Three-path hygiene (#4153): `db.rs` fresh-create includes the columns; `migration.rs` upgrade block adds them; the pinned `assert_eq!(version, N)` test moves in the same change; verify the cascade file exists (#4484). crt-055's `cycle_review_index` ALTER and crt-054's new `compaction_events` table are on DIFFERENT tables → no ALTER collision; they take DISTINCT SEQUENTIAL `CURRENT_SCHEMA_VERSION` numbers (whoever merges first is N, the other N+1 — an SM coordination point at merge, lesson #4095). Pre-v5 rows return DEFAULT 0 until the guarded recompute refreshes them when source data is present.

### Consequences
Easier: one migration, one bump, clear single ownership; the crt-047 template is proven; disjoint tables dissolve the SR-04 collision to "pick the next free sequential number at merge." Harder: the three-path + cascade + pinned-test edits must land in one change or a DB path is left on the wrong schema (#4153/#4484); the merge-order version handshake with crt-054 must be honored (lesson #4095). Cross-refs: ADR-002 (the single writer this versions), ADR-004/005/007 (the columns this migrates), crt-054 ADR-008 #5032 (the disjoint-table merge handshake), crt-047 v23→v24 (template), #758 (owns v4, the guarded-recompute path).
