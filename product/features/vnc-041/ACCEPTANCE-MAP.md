# vnc-041 Acceptance Criteria Map

> Source: product/features/vnc-041/SCOPE.md (AC-01..AC-06) + specification/SPECIFICATION.md verification methods.
> Crate is `unimatrix-server`. Verification commands assume the workspace root.

| AC-ID | Description | Verification Method | Verification Detail | Status |
|-------|-------------|--------------------|--------------------|--------|
| AC-01 | Fresh container `serve` (no (a) present, `config.http.enabled == true`) writes the annotated global `config.toml` exposing `DEFAULT_CONFIG_TOML` knobs at `paths.data_dir.join("config.toml")` (`/data/.unimatrix/<path-hash>/config.toml`); a subsequent boot with the file present does NOT overwrite it. Container/HTTP path ONLY. Gate is `if config.http.enabled` (ADR-004), NOT `base_dir`. | test | `cargo test -p unimatrix-server` — integration test: `serve` with `http.enabled=true` + empty data dir asserts (a) exists at the resolved path-hash path with template knobs; second boot asserts content/mtime unchanged. Also asserts seed fires with `base_dir = None` (proves gate is `http.enabled`). | PENDING |
| AC-02 | `register <slug>` writes `{base_dir}/{slug}/config.toml` — the exact path `resolve_slug_config` reads — and Feature A's resolver picks it up on the next restart with no hand-placement. | test | `cargo test -p unimatrix-server` — run `register <slug>`, assert (b) exists at `per_slug_data_dir(base_dir, slug).join("config.toml")`; then run `resolve_slug_config` for that slug and assert it reads the seeded file (round-trip, no hand-placement). | PENDING |
| AC-03 | Per-slug seed annotations match Feature A's classification field-for-field — overlayable keys editable, global-locked keys INCLUDED but commented-out + "managed globally" — rendered from the registry; a classification flip flips the annotation (proven, not restated). | test | `cargo test -p unimatrix-server` — for every entry in `PER_SLUG_CONFIG_CLASSIFICATION`, assert overlayable ⇒ editable line, locked ⇒ commented-out + "managed globally" line in the rendered seed. Plus a flip test: stub one key's `OverlayDisposition` and assert the rendered legend line flips. Field-less locks (`permissive`/`tls`/`http`/`*_sha256`) render "managed globally" with no editable knob. | PENDING |
| AC-04 | A per-slug file setting a global-locked key (`[embedding].model`, a transport field, `permissive`) produces ONE `tracing::warn` PER IGNORED KEY, once per boot (not per request), naming key + slug; value remains ignored; daemon behavior otherwise unchanged (WARN only). | test | `cargo test -p unimatrix-server` — per-slug file (b) sets a locked key; capture `tracing` output across repeated `resolve_slug_config` calls in one boot; assert exactly one WARN per ignored key naming key+slug, value still ignored, resolution output identical to the no-WARN path. WARN surface derives from `is_per_slug_overlayable == false`. | PENDING |
| AC-05 | Seeding never clobbers an existing target file (global (a) or per-slug (b)) — operator-authored config survives a re-register / re-boot. Uses the `create_new` no-clobber primitive; no `path.exists()` precheck. | test | `cargo test -p unimatrix-server` — pre-place operator content in (a) and (b); run container `serve` + `register <slug>`; assert both files byte-for-byte unchanged. Confirm `AlreadyExists` is a silent no-op and the seed path has no separate existence precheck. | PENDING |
| AC-06 | REGRESSION SENTINEL — a local STDIO / single-project deployment (`config.http.enabled == false`) forces no new config file and its config behavior is byte-for-byte identical to pre-vnc-041. | test | `cargo test -p unimatrix-server` — sentinel test: local `serve` (`http.enabled=false`) with empty home `.unimatrix`; count files before/after, assert delta == 0; assert resolution behavior matches the pre-vnc-041 baseline. Negative control: same harness on the `http.enabled=true` path shows delta > 0 (sentinel is not trivially passing). | PENDING |
