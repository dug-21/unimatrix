## ADR-003: Per-slug seed annotations RENDER from `PER_SLUG_CONFIG_CLASSIFICATION` at runtime — a derived legend, not a hand-list; reuse `DEFAULT_CONFIG_TOML`, no new serializer

### Context
SCOPE Goal 3 / AC-03 (the one-way A→B contract): the per-slug seed's per-key annotations —
which keys are per-slug-overlayable (editable here) vs global-locked (managed globally,
value ignored) — must RENDER from Feature A's `PER_SLUG_CONFIG_CLASSIFICATION` /
`is_per_slug_overlayable` (config.rs:4447/4552). AC-03 demands "proven, not restated": a
classification flip must flip the seed annotation. OQ-1 (RESOLVED): global-locked keys are
INCLUDED in the seed, rendered commented-out and marked "managed globally" — showing them
documents the per-slug/global boundary.

Constraints that shape the render:
- SR-02 (High): a hand-enumerated locked surface drifts from A. The render MUST iterate the
  registry, never restate a key list in B.
- SR-03 (Med): the registry mixes shapes — `inference.w_sim` maps to a real editable field;
  `permissive` has NO `UnimatrixConfig` field (it is the daemon process flag); `tls`/`http`
  are transport sections never read at the per-slug seam. The render must handle field-less
  locks (`permissive`) without inventing an editable knob for them.
- SCOPE Non-Goal "no new serializer": `DEFAULT_CONFIG_TOML` (config.rs:4605) is a
  hand-curated annotated static string, explicitly NOT serialized from the struct (the
  structs are `Deserialize`-only; no `Serialize`). vnc-041 must NOT add a struct→TOML
  serializer. The Reuse constraint locks "existing config-write / template machinery."

### Decision
A new `render_per_slug_seed_toml() -> String` in `infra/config.rs` (colocated with the
registry and the template it consumes) builds the per-slug seed body in two parts:

1. A **classification-derived legend block**, generated by iterating
   `PER_SLUG_CONFIG_CLASSIFICATION` in order and emitting, for EACH entry, one commented
   line keyed on `disposition`:
   - `PerSlugOverlayable` → `# {key} — editable here (overlays the global per-slug)`
   - `GlobalLocked` → `# {key} — managed globally; a value here is IGNORED`
   This block is the AC-03 contract surface: it is produced by `match`-ing on
   `OverlayDisposition` over the registry, so a classification flip (or a new entry)
   changes the rendered legend mechanically (SR-02/SR-07). It restates nothing — the key
   strings and dispositions come from A's `const`. Field-less locks (`permissive`,
   `tls`, `http`) appear in the legend as "managed globally" with no editable knob, which
   is the correct treatment for SR-03 — they are documented, not seeded as editable.

2. The **reused `DEFAULT_CONFIG_TOML` knob template** appended below the legend, verbatim,
   as the editable-knobs body. This satisfies "no new serializer / reuse template
   machinery": the per-slug-overlayable knobs an operator actually edits are the same
   commented field lines `DEFAULT_CONFIG_TOML` already documents.

The seed body = legend (rendered from the registry) + a per-slug header + the reused
template. `render_per_slug_seed_toml` is the C2 component; its output is passed to the
ADR-001 no-clobber writer by the ADR-002 per-slug seed call site.

NOTE on granularity (OQ-A in ARCHITECTURE §9): the legend-block shape is the architect
recommendation because it keeps the proven static template untouched and makes the AC-03
flip-test trivial. If the spec writer determines AC-03 requires per-key tags woven INLINE
into the template body, that is a heavier render but the same principle holds — the inline
tags MUST still be produced by iterating the registry, never by a second hand-list.

### Consequences
- Easier: the split has exactly one owner (A); B's annotations are a binding, not a copy —
  the crt-031 literal-duplication divergence A's ADR-004 (#5217) prevented for the verdict
  table and merge is now also prevented for the seed annotations (SR-02/SR-07).
- Easier: the AC-03 "proven, not restated" test is a direct render assertion — flip an
  entry's `disposition`, assert the rendered legend line flips editable↔managed-globally.
- Easier: field-less locks (`permissive`) are handled by the legend uniformly (SR-03) — no
  attempt to render an editable knob for a key with no config field.
- Easier: Non-Goal honored — no struct `Serialize`, no new merge; the editable-knob body is
  the existing `DEFAULT_CONFIG_TOML` reused.
- Cost / forcing function: `render_per_slug_seed_toml` couples to the registry's `key`
  strings and `OverlayDisposition` variants; a future variant added to `OverlayDisposition`
  is a compile break here (intended — the render must classify every disposition).
- Known limitation (documented): the legend keys are the registry's dotted identifiers
  (e.g. `inference.w_sim`), which are stable map keys, not guaranteed 1:1 with the
  template's `[section]` line layout. The legend names the key; the template documents how
  to set it. This is acceptable — the legend is a boundary map, the template is the editor.
- Cross-references vnc-040 ADR-004 (#5217 — the single-source classification this consumes),
  ADR-001 (no-clobber writer for the rendered body), ADR-005 (the WARN that uses the SAME
  registry for the runtime-ignored mirror of this seed-time annotation).
