## uni-zero product review (advisory — human judgment required)

**Gate**: scope-review | **Stance**: Proceed to design. This is the right problem now, and the coupling of "remove no-slug" with "make registration one-step" is the correct framing — but watch that the feature stays a *routing/devex* fix and does not balloon into a deployment-model rebuild via the one-step-registration mechanism (OQ-4).

### Vision / roadmap fit

Advances goal #4946 (`personal-cloud`). The fit is direct and the timing is right: this is the first real end-to-end dogfood of the headline "one container, one bundle, one command" promise, and it found that promise non-functional. A goal's headline claim being broken on first contact is the highest-priority class of work — it sits ahead of net-new feature surface (#732 metrics, #682 Rust-hook retirement) because it invalidates the destination already declared shipped.

The scope is also a genuine *correction* of vnc-034 (#733, closed), not new territory. vnc-034's goal entry #4946 already states the intended invariants this feature restores to truth:
- "register a project ... vs attach a client ... errors if unregistered" — the no-slug default route is exactly the path that violated "errors if unregistered," so removing it brings the code back into line with the stated contract.
- "project identity comes from the transport ... NEVER the request payload, so cross-project mis-targeting is unrepresentable" — slug-in-bundle (objective 3) and per-slug observe (objective 5) close the one path (#4946: client-side slug append) where identity was decided after the trust boundary. This is the seam vnc-034 promised but did not fully deliver for the bundle/observe path.

So the work does not constrain the roadmap — it pays down a contract debt that would otherwise block every downstream personal-cloud item from being trustworthy. It also keeps the enterprise-extends-not-rearchitects line intact: the scope explicitly defers RBAC/authz/N:N and frames isolation as a routing property, consistent with #4946 and the standing guidance to not over-state defensive structure (the SCOPE does this well in its Proposed Approach rationale).

**In-flight adjacency to flag, not block:**
- **#735** (vnc-034 follow-up) touches the same first-boot surface: token-to-stdout on first boot (`token.rs:101`) and `router.rs` >500 lines. vnc-038 reworks the route grammar in `router.rs` and the first-boot path. These should be sequenced so vnc-038 either absorbs the `router.rs` extraction opportunistically or explicitly leaves #735 to land after. Two features editing first-boot + router concurrently is a merge-collision risk worth deciding up front.
- **#767, #768, #769** are correctly held as non-goals. #768 (stale remote docs) is the one I'd watch: a hard cutover that changes the attach command *guarantees* the docs go stale, so #768 becomes a near-certain immediate follow-up. Not a dependency, but pre-commit to it as a fast-follow so the next dogfood doesn't trip on docs.

### Approach commentary

**Strengths.** The scope is unusually well-grounded — every claim is pinned to a file:line, the three #766 fix surfaces are enumerated, and the integrity stake is stated as a concrete unrollbackable-corruption risk rather than abstract "security." The decision to fix by construction (remove the route) rather than reroute the 404 is the right instinct: patching `/v1/observe` would leave the pollination hole (#4946's identity-after-trust-boundary) open. The hard-cutover stance (no compat no-slug fallback) is correct *because* a retained default route preserves exactly the hole being closed — keeping it would be incoherent with the goal.

**Concerns:**
1. **OQ-4 is the whole feature's risk and is under-bounded.** "How does a running daemon make a new project routable without restart" is genuinely the hard part, and the three candidate mechanisms (live config write+reload / admin endpoint / dynamic registry) have very different blast radii. A dynamic registry that replaces the boot-once `[[projects]]` read is the cleanest long-term shape and most aligned with #4946's single-funnel, but it is also the largest change. SCOPE flags a design-time spike — I'd make that a hard gate: do not let design proceed past architecture without resolving OQ-4 first, because OQ-2/3/5 all partly depend on it.
2. **Scope-creep vector.** "Frictionless one-step self-registration" is framed (objective 2/4) as equal in standing to the bug fix. That is the right product call — removing no-slug without it makes devex strictly worse — but it is also the lever that could turn a routing fix into a deployment-UX rebuild. Recommend the design hold a bright line: self-registration must do exactly two things (create per-slug dir + make routing live) and nothing more. Resist absorbing model provisioning (#767), token UX (#735), or any "while we're in here" first-boot polish.
3. **Local UDS (ADR-004) under mandatory identity (AC-10, OQ-1) is the quiet risk.** The cloud story is clean; the local single-project path-hash install is where "mandatory identity" rubs against "zero-step local default." If first boot now demands a slug even for the local install, that regresses the local devex that #4946 calls "the common case and the seam's proving ground." OQ-1's derive-vs-require choice is really a local-devex decision wearing a migration hat — see below.

### Recommended answers to open questions

- **OQ-1 (first-boot identity for surviving path-hash store — HUMAN DECISION):** Recommend a hybrid biased toward **derive (b), with the derived slug surfaced and overridable**. Pure-require (a) regresses the local install — #4946 names local as the common case and proving ground; forcing every existing daemon to be hand-fed a slug on upgrade is the same friction this feature exists to remove. Derive a default slug from the project-dir basename, adopt the surviving store by *re-attach/open never genesis* (per the Constraints + State B precedent), and print a loud actionable line stating the adopted slug and how to rename. Rationale: zero-friction on the happy path, but never silent — the operator sees the identity chosen and can correct it. This keeps AC-09's "never silent default/corruption" while honoring AC-10.

- **OQ-2 (what bundle schema carries the slug):** Recommend a **single `slug` identity field at `v:2`**, with the server routing observe per-slug — *not* distinct mcp/observe endpoint fields. Rationale: identity-in-bundle + server-routed observe yields one invariant (the bundle names the project; the server owns route shape), keeping the client a thin decoder that never derives or composes routes. Explicit endpoint fields push route-composition responsibility back to the client — the exact post-trust-boundary logic this feature is removing. One field, two derived routes server-side, is the simpler and safer invariant.

- **OQ-3 (per-slug observe: server-routed vs client-derived):** Recommend **server-routed `/v1/{slug}/observe`**, accepting the reserved-slug reshaping cost. This puts observe on the same per-request funnel as MCP (#4946's "one isolation seam"), making objective 5/6 a structural property rather than a client-side convention to get right in two places. Client-derived is lower immediate blast radius but leaves observe identity derivation as a separate code path — precisely the "two places to get right" the SCOPE itself names as the risk. Pay the routing-contract cost once; it collapses the invariant.

- **OQ-4 (one-step live-registration mechanism):** Recommend the design **spike a dynamically-read registry that the resolver consults per-request**, replacing the boot-once `[[projects]]` read, over the live-config-write-and-reload option. Rationale: a config-file write+reload mechanism couples routing truth to a mutable on-disk file and a reload path that can partially fail; a registry the resolver reads is the natural extension of the existing per-request `resolve_store` seam and the cleaner enterprise-extends substrate (it is where a future RBAC/claims check would live). An authenticated admin endpoint is the *trigger*; the registry is the *state*. Treat these as two parts of one answer, not competing options. **This OQ must be resolved before design exits architecture** — it gates OQ-2/3/5.

- **OQ-5 (does removing the default alias retire `DefaultResolver`, or is single-project just N=1):** Recommend **single-project = N=1**: retire `DefaultResolver` and the `/v1/tools/... -> Default` grammar arm, express the single-project deployment as one registered slug through the same resolver. Rationale: a special-case resolver is a second code path that can diverge from the multi-project funnel — the opposite of #4946's single-seam invariant. If OQ-4 lands on a dynamic registry, N=1 falls out for free and there is no second resolver to maintain.

- **OQ-6 (sibling-issue inseparability — #767 embedding model):** Recommend **confirm-and-flag, do not absorb**, and bias toward it being a *dependency* rather than in-scope. If one-step self-registration's stated value is "creates a project that is live and usable," and a freshly provisioned store cannot embed without a model (#767), then objective 2's "usable" claim is hollow without #767. Recommend design explicitly tests the AC-07/AC-08 happy path on a *fresh* provisioned store; if the Ping/observe round-trip needs embedding to succeed, declare #767 a hard predecessor and sequence it first — but keep its fix in #767, not in this feature's diff.

### Recommended actions

1. **Approve scope to enter design**, with OQ-4 designated a hard architecture-gate (resolve the live-registration mechanism — recommend dynamic registry — before any other component design proceeds).
2. **Decide OQ-1 now** (it is a local-devex policy call, not purely a migration detail): recommend derive-and-surface (b-hybrid). Capture the decision in the design ADR set so AC-09/AC-10 are testable.
3. **Sequence against #735**: decide whether vnc-038 absorbs the `router.rs` extraction (likely yes, since it rewrites the route grammar there) or explicitly defers #735 to after merge. Avoid concurrent edits to first-boot + router.
4. **Pre-commit #768 (docs) as a fast-follow** — the hard cutover guarantees the attach docs go stale; do not let the next dogfood fail on documentation.
5. **Hold the scope line in design**: self-registration creates dir + makes routing live, nothing more. No first-boot polish, token UX, or model provisioning absorbed into this diff.
6. **Confirm OQ-6** by testing the fresh-store Ping/observe path during design; if embedding is required for "usable," declare #767 a predecessor and sequence it first.
