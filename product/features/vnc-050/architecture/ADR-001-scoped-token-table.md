## ADR-001: Scoped Token Table — Hashed at Rest, Tombstone Revoke, Constant-Time Full Scan, Live Reload, Fail-Closed

### Context
`StaticTokenValidator` (`http/auth.rs`) holds one 32-byte token from `{data_dir}/token` and returns a fixed all-capability identity (vnc-021 ADR-001, #4665). vnc-050 needs many tokens, each `read|read-write` and bound to `allowed_slugs` (AC-07/AC-10). OQ-4 fixes SHA-256 at rest. SR-02: a hash-keyed map lookup is not constant-time. SR-03: `client-bundle --revoke` runs as a separate CLI process while the server runs, and AC-16 requires the next call to get 401, so revocation must take effect without a restart. OQ-5: the legacy token stays enabled by default, and the operator can turn it off. Human decision (V-2a): revoke is a tombstone, because AC-11 audit rows carry the token label and deletion would orphan attribution and let a reused label inherit history. Human decision (V-2c): the legacy disable is a config setting with an env override, following `http.enabled` / `UNIMATRIX_HTTP_ENABLED`, so it fits the PL-2 versioned config contract.

### Decision
- **File**: `{data_dir}/tokens.json`, mode 0600, canonical JSON `{"v":1,"tokens":[{"label","sha256","mode","allowed_slugs","created_at","revoked_at"}]}`. `label` matches `^[a-z0-9][a-z0-9-]{0,62}$` and is unique. `sha256` is 64 lowercase hex chars of SHA-256 over the raw 32 token bytes. `mode` is `"read"` or `"read-write"`. `allowed_slugs` is a non-empty array of `ProjectSlug`. `revoked_at` is `null` (active) or a `u64` epoch-seconds timestamp (tombstone). Unknown keys, a duplicate label or an empty slug list reject the whole file.
- **Revoke = tombstone**: `--revoke` sets `revoked_at` and keeps the whole record (hash, label, mode, slugs, created_at). Records are never deleted. A label is unique across active and revoked records forever, so minting with any existing label is an error. Revoking an already-revoked label exits non-zero with no state change.
- **Writers** are only `client-bundle --headless` and `client-bundle --revoke`. A writer takes an exclusive `flock` on `{data_dir}/tokens.lock`, reads the file, mutates it, writes `tokens.json.tmp` (0600), fsyncs it, then `rename`s it over the file. The file stores no plaintext secret. The secret is printed exactly once, inside the bundle on stdout (vnc-038 ADR-008, #5088).
- **Validator**: `TokenTableValidator` implements the existing `BearerValidator` trait and wraps the legacy validator. For each presented token it hex-decodes the value and checks the length is 32 (an early reject is allowed here, same as ADR-001 vnc-021). It then (1) compares against the legacy token with `ct_eq`, if the legacy token is enabled, and (2) computes `sha256(presented)` and `ct_eq`s it against **every** entry, revoked ones included. It never breaks out of the loop early. The match is recorded in a `subtle::Choice`/index accumulator. No `HashMap` keyed by hash is used. A match on a tombstone is a 401 identical to an unknown token, decided after the full scan.
- **Live reload**: the validator keeps `RwLock<Snapshot{entries, stamp}>`, where `stamp = (mtime_ns, len, inode)` of `tokens.json`. On every `validate` call it `stat`s the file. If the stamp changed, it re-reads and re-parses under the write lock. A missing file is valid and means an empty table. A file that exists but does not parse **fails closed**: every scoped token gets 401, `tracing::error!` is logged once per stamp, and the legacy token keeps working. A last-good snapshot is never served, because that would revive revoked tokens.
- **Legacy disable**: new key `http.legacy_token_enabled: bool` (serde default `true`; absent key in any existing config file keeps today's behavior, so PL-2 versioned config stays backward compatible). Env override `UNIMATRIX_LEGACY_TOKEN_ENABLED`, applied after the file merge exactly like step 3c (`UNIMATRIX_HTTP_ENABLED`): `true|1` / `false|0` override, empty = no override. One deviation from the `http.enabled` pattern: an unrecognized value is a boot error, not a debug-logged no-op, because silently keeping a credential enabled is unsafe. When disabled, a legacy-token request gets 401 with the body `"legacy token disabled"` (SR-14). Modularity: `infra/config.rs` is over the cap, so it gets only the field, its default line, and a 3-line override step calling `infra::legacy_token_config::resolve_legacy_token_override(Option<&str>) -> Result<Option<bool>, ConfigError>`. The parser and its tests live in the new module `infra/legacy_token_config.rs`. The listener reads `config.http.legacy_token_enabled` when building `TokenTableValidator`.

### Consequences
- Revocation takes effect on the next request, at the cost of one `stat` per request.
- The scan is O(n) over the tokens. That is fine for the expected table size (tens of tokens).
- If the token table is corrupt, scoped access stops but legacy and local access keep working. An operator can fix the file without being locked out.
- The file grows monotonically with revoked records. Acceptable at the expected scale; `--list` shows tombstones.
- Writers must run on the server host, the same constraint the existing `client-bundle` already has (SR-09).
