Component: `crates/unimatrix-server/src/mcp/graph_read_inverse.rs`
Responsibility: `handle_inverse` — validate inverse-mode params, build dynamic N-LEFT-JOIN
antijoin SQL, execute via `store.read_pool_server()`, return `InverseResponse`.

## Integration Test Expectations (AC-27, AC-28)

### AC-27 — test_context_graph_inverse_single_type

**Location**: `test_tools.py`, after the vnc-019 block.
**Fixture**: `server` (fresh DB).

**Fixture setup**:
1. Store `entry_active_no_edge`: active source entry with no incoming Cites edge.
2. Store `entry_active_with_edge`: active source entry; add an incoming Cites edge
   from another entry (use `server.context_edge("add", other_id, "Cites", entry_active_with_edge_id)`).
3. Store `entry_deprecated_no_edge`: store entry, then deprecate it via `context_correct`
   (supersede it); the deprecated entry has no incoming Cites edge.

**Action**:
```python
resp = server.context_graph(
    "inverse",
    category="source",
    missing_edge_types=["Cites"],
    agent_id="human",
    format="json",
)
```

**Assertions**:
- Response is a tool success (no error code).
- `data["entries"]` is a list.
- `entry_active_no_edge_id` IS in the returned entry IDs.
- `entry_active_with_edge_id` is NOT in the returned entry IDs.
- `entry_deprecated_no_edge_id` is NOT in the returned entry IDs (R-10 guard).
- `data["total_returned"] == len(data["entries"])` (AC-06).

**Risks mitigated**: R-05 (partial), R-10, AC-27

### AC-28 — test_context_graph_inverse_and_semantics

**Location**: `test_tools.py`.
**Fixture**: `server` (fresh DB).

**4-state fixture** (mandatory per R-05 — a 2-state fixture cannot distinguish AND from OR):

| Entry | Has Cites incoming? | Has Supports incoming? | Expected in result? |
|-------|--------------------|-----------------------|---------------------|
| entry_a | No | No | YES (missing both) |
| entry_b | Yes | No | NO (has Cites) |
| entry_c | No | Yes | NO (has Supports) |
| entry_d | Yes | Yes | NO (has both) |

**Fixture setup**: Store 4 source entries. For entries b and d, add an incoming Cites edge
from a "donor" entry. For entries c and d, add an incoming Supports edge from a "donor" entry.

**Action**:
```python
resp = server.context_graph(
    "inverse",
    category="source",
    missing_edge_types=["Cites", "Supports"],
    agent_id="human",
    format="json",
)
```

**Assertions**:
- `entry_a_id` IS in results.
- `entry_b_id` is NOT in results (has Cites — missing only Supports, not both).
- `entry_c_id` is NOT in results (has Supports — missing only Cites, not both).
- `entry_d_id` is NOT in results.
- `data["total_returned"] == 1`.

**Critical assertion**: entries b and c (missing only ONE type) must NOT appear. This is
the AND-vs-OR distinguishing assertion. If it fails, the antijoin uses OR semantics.

**Risks mitigated**: R-05 (AC-28)

## Edge Cases

- `missing_edge_types` with duplicate entries (e.g., `["Cites","Cites"]`): test that the
  SQL builder either deduplicates or produces a result set that is still correct. Write one
  test `test_handle_inverse_duplicate_edge_types_not_an_error` — assert no panic or SQL
  error; behavior (dedup or double-join) is acceptable as long as result is correct.
- `inverse` mode with 10 `missing_edge_types`: `test_handle_inverse_10_types_does_not_error`
  — verify SQLite can handle 10 LEFT JOINs without hitting a compile-time limit.
- Empty category (e.g., `category="goal"` with no goal entries in DB): assert
  `{ entries: [], total_returned: 0 }` — not an error.
