# Test Plan — parity-corpus-uds (UDS layer of the parity corpus)

Component 10 / ADR-001, ADR-003, ADR-007 / FR-20..FR-26 / **AC-01, AC-02, AC-03, AC-04, AC-06, AC-07, AC-11** /
Risks R-01, R-05, R-08, R-09, R-10, R-12, R-16, R-17. The integration backbone. Extends the vnc-026 corpus
(oracle/golden/drift, entry #4790) with a UDS layer. Reuse `test/helpers/real-server.js` (extend with a UDS
connect helper — cumulative infra, never a parallel scaffold). Goldens generated Rust-side via `parity_corpus_gen.rs`;
`scripts/regen-parity.sh` must produce zero diff in CI.

## Layer a — framing fixtures (AC-01, offline, no listener)

- `test_uds_frames_byte_identical_to_wire_rs_fixtures` — transport-uds frames for the post-reduction corpus byte-compared against committed Rust-generated `wire.rs` framing fixtures. Boundary cases at exactly 1,048,576 B both directions (R-18). MANIFEST arm-coverage audit mirrors `parity-layer1.test.js` (every arm → ≥1 case; vacuous-pass guard #4452).

## Layer b — live UDS listener round-trip (AC-03, R-01)

Requires a cargo-built binary; hard-fail-never-skip if absent. New UDS scenarios on the extended `real-server.js`:
- `test_uds_roundtrip_identical_hookrequest_frames` — full post-reduction corpus framed by transport-uds → live listener decodes identical `HookRequest` (FR-20b). Corpus EXCLUDES retired events (FR-21) and lone-surrogate inputs (FR-22).
- `test_fnf_max_1mib_frame_recorded_complete` — a 1 MiB FNF frame → daemon recorded the event completely (ADR-003 §6 truncation contract; R-01 s1).
- `test_fnf_kill_mid_write_no_silent_truncation` — kill the client mid-write → either full delivery or a clean server-side frame error, NEVER a silently truncated accepted event (R-01 s2).
- `test_fnf_epipe_stays_debug_classified` — normal TS FNF produces no WARN-level server noise (#3448, R-01 s5).

## Layer c — sync-trio stdout goldens (AC-03, R-09)

- `test_uds_sync_trio_stdout_byte_identical_to_rust_hook` — ContextSearch (plain), ContextSearch-under-SubagentStart envelope, CompactPayload, Ping/briefing → byte-identical stdout vs committed Rust-hook goldens (corpus layers b, c).
- `test_entries_text_body_has_injection_header` — `Text` body for Entries starts byte-exactly with `--- Unimatrix Context ---\n`; SubagentStart envelope dispatch on that header works over UDS (the #4778 bug class, R-09 s1-s2).
- `test_briefing_body_verbatim_no_header` — BriefingContent body is `content` verbatim (transform.js plain path).
- `test_shared_core_http_vs_uds_body_identical` — HTTP `Accept: text/plain` body == UDS `Text` body for the same request, end-to-end (R-09 s3, parity-by-construction).
- `test_empty_injection_sync_no_stdout` — empty injection → `Ack` → 204-equivalent → no stdout (ADR-001 §4).

## AC-11 — frozen contract end-to-end (R-08 s4, the strongest proof)

- `test_frozen_rust_hook_e2e_sync_trio_unchanged` — the compiled frozen Rust binary (no `accept`) run against the UPDATED daemon → full sync trio byte-unchanged; the daemon returns typed JSON (never `Text`) to it. This is the live proof that the additive wire change cannot crash deployed frozen hooks.
- `test_queued_frames_never_carry_accept` — frames in the queue never contain `accept` (transport adds it at serialization); HTTP frame goldens byte-unchanged; a queued sync frame is impossible by construction (only FNF enqueues) — assert.

## AC-02 / R-05 — hash-fixture corpus (drift-checked)

- Rust-generated golden hash fixtures `(layout, expected root, expected hash)` for: main root, deep subdir, linked worktree, symlinked path, non-git fallback + the pinned corrupt-worktree divergence. The TS suite replays them through `walkToProjectRoot`+`computeProjectHash` (consumed by config-transport-selection.md). Generated by the corpus generator so a future Rust resolution change breaks the drift check instead of silently splitting hashes. Generator must create/clean up real worktrees/symlinks.

## AC-04 / R-10 — cross-transport replay (both directions)

- `test_replay_uds_enqueue_to_http` — enqueue under UDS (no daemon) → next spawn resolves HTTP config → replay accepted at `/observe` with the fresh token.
- `test_replay_http_enqueue_to_uds` — enqueue under HTTP (server down) → next spawn resolves UDS → replay accepted by the live listener.
- `test_session_id_split_pinned` — HTTP-ingested replays land under `http-{sid}`; UDS under raw `{sid}` — accepted, pinned so a future change is deliberate (R-10 s2).
- `test_poison_pill_does_not_abort_replay` — a malformed JSON queue file is skipped; subsequent frames still replay (R-10 s4).
- `test_replay_order_preserved_failed_leaves_queued` — replay-before-send order preserved; a failed replay leaves the frame queued (FR-26).

## AC-07 — delta-over-UDS buffer merge (end-to-end)

- `test_transcript_delta_over_uds_merges_into_f2_buffer` — `transcript_delta` RecordEvents via UDS through `listener.rs:785,1025` into the F2 buffer; assert PreCompact block CONTENT (reuse `precompact()`/`prepopulateBuffer()`), not just frame acceptance.

## AC-06 / R-17 — PreCompact single block

- `test_uds_precompact_single_server_built_block` — stream deltas over UDS, fire PreCompact → exactly one server-built block in the golden; TS never client-side-prepends. Mixed-client double-prepend is a documented UNSUPPORTED config (one project, one client) — no test (R-17).

## R-12 — SubagentStop server-side independence (lifecycle proof)

- `test_no_subagentstop_full_lifecycle` — full session lifecycle (SubagentStart → events → Stop) with SubagentStop NEVER sent → session closes normally, buffers finalize, no leaked state (converts the ADR-004 assumption into an asserted contract).

## R-13 — no-daemon queue bounds (enqueue-only path)

- `test_enqueue_only_bounds_respected` — enqueue past MAX_FILES with no listener → count ≤ 500, total ≤ 5 MiB, oldest evicted first; a 25 h-old pre-seeded frame is age-pruned. Exactly one stderr line per failed spawn, sync silent, exit 0.

## AC-05 — latency (perf job)
- `test_uds_p95_under_20ms` — F3 AC-13 protocol against the live local socket incl. project-root detection; FNF and sync measured separately. 40 ms timeout constants asserted (not load-bearing for p95). Linux-only Layer-2-scoped job.

## R-16 — dogfood drop detector (post-merge, NOT an F4a gate)
Documented procedure with concrete thresholds (state.json breadcrumbs: failureClass `connect`, queueDepth;
queue-residue emptiness; event-count drop > 50% day-over-day → one-line settings revert). Exists before switchover; no F4a test.

## Accepted divergences the corpus must except EXACTLY (FR-22)
Lone-surrogate inputs excluded from byte-compare cases (node:test todo stays tracked); no bare probe connection;
PreCompact client-block source (Rust-only); event-set divergence by design. Any NEW divergence is fixed or registered
by explicit decision — never silently tolerated.
