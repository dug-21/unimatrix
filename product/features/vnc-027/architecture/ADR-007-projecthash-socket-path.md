## ADR-007: Socket Path Derived from the Existing config.js projectHash — SR-12 Settled Empirically, Hash-Fixture Corpus Required

### Context

Local mode connects to `~/.unimatrix/{projectHash}/unimatrix.sock` (hook.rs:180-184).
A TS/Rust hash mismatch is a silent total failure: the client enqueues forever
against a socket path that never exists (SR-12, High). The risky case is
worktrees — hook stdin `cwd` for worktree-isolated subagent events may carry the
worktree path (OQ5, unanswered by ass-072), and #679 only just fixed Rust
worktree-root resolution (`resolve_git_file`), with the TS port landing in the
same fix. The F3 client already derives `projectHash` for its state dir
(config.js, oracle-cited port of `project.rs::compute_project_hash` +
`detect_project_root`).

### Decision

1. **Single derivation, zero new config**: `config.resolve()` in UDS mode derives
   `socketPath = path.join(home, ".unimatrix", projectHash, "unimatrix.sock")`
   from the SAME `walkToProjectRoot` + `computeProjectHash` it already uses for
   `stateDir`. No second implementation, no override key (F5 owns any knob). The
   state dir and socket path can therefore never disagree with each other.
2. **Empirical settlement (executed 2026-06-08 in this workspace)**:
   - TS `walkToProjectRoot` + `computeProjectHash` for `/workspaces/unimatrix`,
     a freshly created git worktree (`/tmp/vnc027-wt-check`), and a deep subdir
     all returned root `/workspaces/unimatrix` and hash `0d62f3bf1bf46a0a`.
   - `sha256("/workspaces/unimatrix")[..16]` independently = `0d62f3bf1bf46a0a`
     (algorithm parity with `compute_project_hash`: first 16 hex of SHA-256 over
     the UTF-8 canonical path).
   - The live daemon's data dir is `~/.unimatrix/0d62f3bf1bf46a0a/` — the
     production Rust-side hash matches the TS-computed hash exactly.
   - Rust tests already assert main-vs-worktree hash equality
     (project.rs:364-427, #679).
   Consequence for OQ5: whether or not subagent hook `cwd` carries the worktree
   path is now immaterial to socket derivation — both implementations resolve a
   worktree cwd to the main-repo root and the identical hash.
3. **Hash-fixture corpus (binding test contract)**: the parity corpus gains
   Rust-generated golden hash fixtures — `(input layout, expected root, expected
   hash)` for at least: main repo root, deep subdir, linked worktree, symlinked
   repo path (realpath/canonicalize parity), and a non-git directory (resolved-cwd
   fallback). The TS suite replays them through `walkToProjectRoot` +
   `computeProjectHash`. Generated by the existing corpus generator mechanism
   (vnc-026 ADR-001 oracle/golden/drift), so any future Rust-side resolution
   change breaks the drift check instead of silently splitting hashes.
4. **Known benign divergence (documented, excepted)**: on an unreadable/dangling
   `gitdir:` target, Rust `detect_project_root` errors and hook.rs falls back to
   the raw cwd, while TS falls back to the realpath of the containing dir
   (config.js:79 doc). Both are failure-mode fallbacks for a corrupt worktree; the
   fixture corpus pins the healthy layouts and this case is enumerated as an
   accepted divergence, not silently ignored.
5. **Soak confirmation (OQ5 residual)**: during the dogfood soak (ARCHITECTURE.md),
   capture one live SubagentStop/SubagentStart stderr dump showing stdin `cwd`
   from a worktree-isolated subagent — zero-cost confirmation, not a gate.

### Consequences

Easier: silent local-mode failure from hash drift is closed off by construction
(one derivation) and by drift-checked fixtures (cross-language); no new config
surface; worktree sessions share the main project's daemon, queue, and knowledge
store — the intended semantics (#679).

Harder: the corpus generator grows a fixture family that creates real worktrees/
symlinks at generation time (must clean up after itself); the corrupt-worktree
fallback divergence remains an accepted asymmetry until F6 retires the Rust side.

Cross-references: SR-12, OQ5, #679 (worktree root resolution), vnc-026 ADR-001
(corpus mechanism), ADR-002 (config.resolve mode).
