## ADR-006: `stamp_miss` Canary — Subagent-Gated Inheritance-Drift Invariant (Zero-Tolerance), Pinned CLI Version

### Context

Stamp correctness rests on two emergent, uncontracted Claude Code behaviors (SR-01, High): `--resume` session_id reuse (empirical on claude 2.1.167; 86/86 corpus) and root-session_id inheritance for subagent hook events (ass-072 verified depth-1 root-id inheritance at 328/328 on claude 2.1.167; depth>1 is explicitly unverifiable until Claude Code lifts the subagent-spawns-subagent constraint). A CLI upgrade can silently break attribution with no error path. `health.json` is the content-free breadcrumb (vnc-026 ADR-005) maintained by `state.js` with field-by-field degrade.

The risk this canary exists to detect (SR-01) is narrow and specific: **a CLI upgrade silently breaks root-session-id inheritance, so a _declared_ session's subagent events lose their stamp.** That is worth detecting. Driving unattributed sessions to zero is NOT the goal — the product goal is provenance: ensure sessions that ARE attributed to a topic get recorded that way.

**Supersession of the prior increment rule (product-owner decision, 2026-06-08).** The first cut of this ADR (entry #4818, pre-rev2) incremented on any FNF decoration miss where at least one _other_ session's cycles file existed (`cycles.anyOtherCycleFile`), thresholded in production at `stamp_miss / fnf_record_send_count > 0.20`. That premise is wrong for this repo. Unaffiliated top-level sessions (uni-zero, research spikes) are not an edge case here — they are the normal mode of use, running constantly alongside feature delivery. Counting their coexistence as a near-miss makes the canary noisy by construction: a tripwire that desensitizes if the threshold sits above the noise and false-alarms if below (textbook bad tripwire). The `anyOtherCycleFile` condition was a failed attempt to separate the inheritance-break case from the healthy never-declare case; both have an identical signature (a session_id with no tracker file), so it could not. This revision retires that rule and its threshold.

### Decision

1. **Counter (field/location unchanged)**: `health.json` keeps `stamp_miss` (monotonic within breadcrumb lifetime, zeroed default), maintained by `state.bumpStampMiss(stateDir)` — read-modify-write via the existing breadcrumb machinery, never-throw. Content-free: a count only — no session ids, no paths, no topics (vnc-026 ADR-005 contract preserved). **Only the increment semantics change in this revision**; the field name and location are stable.

2. **Increment rule (AC-06), subagent-gated**: on the FNF decoration miss branch (ADR-002 §2.4), increment `stamp_miss` **iff the event is in subagent context** — the client sees SubagentStart / the hook event is at depth ≥ 1 — AND no `cycles/{session_key}.json` is found, where `session_key` is the (expected-inherited) root session_id the subagent event carries. This is **unambiguous inheritance drift**: a declared root established `cycles/{root_session_id}.json`; a depth ≥ 1 event that should inherit that root id but finds no tracker means inheritance broke. The `anyOtherCycleFile` / concurrent-file condition is **removed entirely**.

3. **Explicit non-increment — structural noise, NOT counted**: a depth-0 top-level session with no tracker is a never-declare session (uni-zero, research, ad-hoc). No increment. SessionRegister/SessionClose frames never reach decoration; the vnc-027 null sentinel short-circuits non-cycle PreToolUse before decoration. Unattributed top-level sessions are the nature of how this repo is used, not a signal.

4. **What it detects (re-scoped)**: drift **within the declared population** — inheritance breaking for a declared root's subagents — not unattributed sessions in general. A future depth>1 grandchild carrying an intermediate id is the same shape: a subagent-context event whose carried id has no tracker → increment, not silent loss.

5. **Invariant (zero-tolerance, replaces the 0.20 threshold)**:
   - **Test-time (hard)**: single-declared-session-with-subagent fixtures assert `stamp_miss == 0` end-to-end (AC-06 (a)); a simulated inheritance-break fixture (a subagent-context event carrying a non-inherited id while the root tracker exists) asserts exactly the expected single increment ((b)); the depth>1 forward-compat fixture asserts a grandchild id lands in `stamp_miss`, not silent loss.
   - **Production**: the test-time invariant carries over — `stamp_miss == 0` is meaningful in production too. Any nonzero growth is real inheritance drift to investigate before trusting new attribution data. **No ratio, no `fnf_record_send_count` denominator, no threshold, no per-deployment baseline measurement, no human re-set ritual.** The canary is a meaningful zero-tolerance invariant again, not a tuned rate signal.

6. **Pinned CLI version**: test assumptions and the IMPLEMENTATION-BRIEF state the verified version — **claude 2.1.167** — for `--resume` id-reuse and depth-1 inheritance. Any CLI bump after vnc-030 ships re-runs the AC-06 fixtures as the drift check (cheap; part of the standard suite).

7. **Open delivery design question (the crux — NOT resolved here)**: the subagent-gated increment assumes the "I am a subagent" signal (depth ≥ 1 / subagent-context detection) is an **independent** client-side signal from root-id inheritance. ass-072 verified depth-1 root-id inheritance at 328/328 on claude 2.1.167 — but that is inheritance _working_. The inheritance-break case may be observationally identical to a never-declare session even client-side **if a broken CLI also strips the subagent's knowledge that it IS a subagent**. Two branches, resolved empirically by delivery before committing to the production canary:
   - **Branch A — subagent-context detection survives the drift (the two signals are independent)** → the client-side subagent-gated canary is strictly better and replaces the prior §2/§4 rule. **This is the design's primary recommendation.**
   - **Branch B — subagent-context detection is co-dependent with inheritance and breaks together** → this drift is not cleanly detectable client-side under that failure. The honest conclusion is to **narrow the canary to its test-time invariant only and DROP the production signal** rather than ship a tripwire that is noisy by construction.
   - **Resolution path**: delivery probes whether subagent-context detection and root-id inheritance are independent client-side signals (e.g. inspect whether SubagentStart / depth indicators are present on hook stdin under a simulated/aged CLI where root-id inheritance is absent). The **test-time invariant ships either way**; only the production canary's existence depends on the probe outcome.

### Consequences

Easier: the canary returns to a meaningful invariant — `stamp_miss == 0` is the contract at test time AND production, so nonzero growth is a clean "investigate inheritance drift" signal rather than a tuned ratio. The 0.20 threshold, its `fnf_record_send_count` denominator, the live-baseline measurement during AC-07, and the human re-set procedure are all eliminated — no tuning ritual, no desensitization tradeoff (this removes the R-19 false-signal source at its root). Healthy unattributed (depth-0) sessions are no longer treated as signal. Harder: the canary now depends on a second uncontracted behavior — client-side subagent-context detection — whose independence from root-id inheritance is unproven (§7 crux); delivery must run the probe before the production canary can be trusted, and under Branch B the production signal is dropped entirely (test-time invariant only). The canary still cannot name the offending session (content-free contract), so a trip means "inheritance drift — run the fixtures and inspect", not "here's the bug".
