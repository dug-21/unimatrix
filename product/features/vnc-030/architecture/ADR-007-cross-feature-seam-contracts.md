## ADR-007: Cross-Feature Seam Contracts — vnc-027 Interception Seam Survival, crt-052 Close/Sweep Interface, #574 No-Race, Marker-Recovery Follow-Up

### Context

Three in-flight features share two files (SR-09/SR-10, pattern #924): vnc-027 (**merged 2026-06-08, F4a**) edited `build-request*.js`/`index.js`/`merge-settings.js` and reduced the hook set (its ADR-004); vnc-030 rebases onto the merged tree and edits `infra/session.rs`/`uds/listener.rs`; crt-052 (delivers last) edits adjacent functions in the same server files and consumes vnc-030's attribution fixes. #574 plans to relocate `cycle_events` writes server-side. The MARKER tier of the precedence chain is deferred (OQ1: no marker recovery exists today) with a follow-up that must not add a second transcript-buffer reader (crt-052 SCOPE warning, line 377).

### Decision

**§1 — Interception-seam survival contract (vs vnc-027, SR-09).** Named assumption vnc-030 relies on, now asserted against the **merged** F4a tree (anchors verified 2026-06-08):

- *Contract*: after vnc-027's hook-set reduction, a `PreToolUse` for `context_cycle`/`mcp__unimatrix__context_cycle` still (a) spawns the hook — the narrowed install matcher `lib/merge-settings.js:49`, `const PRETOOLUSE_CYCLE_MATCHER = "context_cycle|mcp__unimatrix__context_cycle";`, includes both names by construction; (b) flows through `buildCycleEventOrFallthrough` (`build-request-tools.js:314`) with the F-02 exact-equality gate (`build-request-tools.js:322-324`); and (c) yields a CYCLE_* `RecordEvent` frame carrying `topic_signal = topic` — **not** the null sentinel — when `validateCycleParams` passes. The `null` sentinel (`build-request-tools.js:326`/`:334`/`:354`) applies only to non-cycle or invalid PreToolUse paths and is short-circuited at `index.js:366` before transport selection (`:410`).
- *Post-rebase seam-survival test (binding, validated before any vnc-030 server work)*: two end-to-end client fixtures through the `index.js` pipeline against the merged tree —
  1. **Cycle path**: a `context_cycle(start)` PreToolUse asserts the tracker file is created (ADR-001), and a `CYCLE_START` `RecordEvent` frame is sent **with `cycle_stamp` attached carrying `cycle_stamp.topic` (the declared topic), not the sentinel** — i.e. `request !== null`, the frame reaches the tracker write path (`cycles.writeCycle`) and the decoration step stamps it.
  2. **Non-cycle path**: a non-`context_cycle` PreToolUse asserts `buildCycleEventOrFallthrough` returns the `null` sentinel (`build-request-tools.js:326`), `index.js:366` returns at exit 0, and there is **no tracker touch, no canary bump (`state.bumpStampMiss` not called), and no network** (`selectTransport`/`transport.post` never reached).
  This test is vnc-030's tripwire if a later vnc-027 follow-up drifts the matcher or sentinel; it is testable exactly as written because both branch points (matcher string, sentinel return site) are now pinned to real `file:line`.
- *Shared-file discipline*: vnc-030 adds zero logic to `build-request*.js` (ADR-002 §1) — the rebase surface is `index.js` orchestration only, confirmed against the merged tree.

**§2 — Post-fix close/sweep semantics (interface for crt-052, SR-10).** Citable contract:

- `sweep_stale_sessions` returns `SweepResult.resolved_feature` = the session's declared feature whenever `feature_source == Declared` and a feature is set; majority vote applies only otherwise. `process_session_close` resolves `sessions.feature_cycle` the same way. Both fixes are minimal-diff (one guard around the existing `or_else`, one short-circuit before the existing vote/fallback chain) to ease crt-052's rebase of `drain_and_signal_session`/`clear_transcripts_for_feature` in the same files.
- Consequence crt-052 may rely on: its session selection (`state.feature == feature_cycle` + attributed observations) sees declared protocol sessions attributed by contract — a declared session's `feature_cycle` can no longer be flipped by vote at close or sweep, and stamped rows carry `topic_source = 'declared'`.
- Sequential delivery is pinned (vnc-027 → vnc-030 → crt-052); vnc-030 makes no change to `drain_and_signal_session`, `clear_transcripts_for_feature`, or the transcript buffer.

**§3 — #574 interaction: no-race confirmation (SR-12).** #574 relocates `cycle_events` writes from hook-interception recording to the server-side MCP `context_cycle` handler. vnc-030's tracker hangs on the **client-side** PreToolUse interception seam — a different process and a different artifact (client state file vs server DB row). `load_cycle_observations` (observation.rs:308) windows over `cycle_events` DB rows, which both write locations feed with the same rows; the stamp rides observation inserts, not cycle_events. There is no shared mutable state between the MCP-handler write and the client interception, hence **no race**. *Assumption expiry*: this argument was checked against #574's relocation as scoped on 2026-06-08; if #574 merges before vnc-030 delivers, re-verify that (a) cycle_events rows still carry the same timestamps the windowing uses, and (b) PreToolUse interception of `context_cycle` still fires client-side (the tracker's create/update/delete trigger is the client interception, independent of where the server writes its row).

**§4 — Marker-recovery follow-up contract (SR-07).** The precedence chain ships with the MARKER tier as a named hole: fork-resume (scenario 14) and fresh-restart-without-redeclaration fall through to VOTE/NULL until the follow-up lands. The named follow-up issue (**#700**, filed at design-gate exit per SR-07/OQ-D) carries a **binding dependency contract**: marker recovery MUST consume crt-052's transcript snapshot seam — the cycle-review snapshot path over `take_transcripts_for_feature` (Arc-clone-under-registry-lock, byte-copy-under-buffer-lock) — and MUST NOT add a second production reader of `TranscriptBuffer::contiguous_tail` (single-consumer pin, infra/session_transcript.rs:10; sole production consumer is the PreCompact block path, listener.rs:1646). AC-04's wording stays "stamp → (marker when present) → vote-on-NULL" so the missing tier is explicit in the contract, not implied.

### Consequences

Easier: the three-feature file contention is governed by written, testable contracts instead of SCOPE-level assertions; crt-052's design assumptions get a stable interface to cite; the #574 assumption has an expiry condition instead of silent staleness; the marker follow-up cannot recreate the second-buffer-reader hazard. Harder: the seam-survival test is rebase-order-sensitive (meaningless before the vnc-027 rebase — delivery sequencing must run it at the right point); §2's "minimal diff" constrains how elegantly the close-path refactor can be written (deliberate — downstream rebase cost outweighs local elegance).
