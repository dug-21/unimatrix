# nan-019 Acceptance Criteria Map

> Source of truth: `product/features/nan-019/SCOPE.md` §Acceptance Criteria (AC-01..AC-07) plus `specification/SPECIFICATION.md` §Acceptance Criteria, which strengthens AC-06 (pre-merge tag-parity, un-stripped `:v<version>-<arch>`) and adds **AC-08** (dispatch manifest gating) as design-derived mechanics under DECIDED OQ-5. Per lesson #4796 and the `local-gates-linux-only-ci-is-crossplatform` memory, the gate's first real execution is **post-merge on a `v*` tag push** — CI-dependent ACs are "configured + verified locally; GH execution confirmed post-tag," never asserted before execution.

| AC-ID | Description | Verification Method | Verification Detail | Status |
|-------|-------------|--------------------|--------------------|--------|
| AC-01 | On tag `v*` push AND `workflow_dispatch` (NOT `pull_request`), Docker-capable lanes run the smoke against the shipped image on BOTH arches — `smoke-amd64` (`ubuntu-22.04`) and `smoke-arm64` (`ubuntu-22.04-arm`); each runs reuse-pushed-bytes → boot-HTTP-on → register → restart → per-slug write → assert-landed. | grep + manual | (config) In `.github/workflows/release.yml`: `on:` contains `push.tags: ['v*']` and `workflow_dispatch`, excludes `pull_request`; jobs `smoke-amd64` (`runs-on: ubuntu-22.04`) and `smoke-arm64` (`runs-on: ubuntu-22.04-arm`) exist and invoke `bash product/test/infra-001/scripts/docker-http-posture-smoke.sh`. On a `v*` push each smokes its un-stripped per-arch tag `:v<version>-<arch>`; on dispatch each smokes `:latest-<arch>`. (execution) Confirm both jobs ran on hosted runners in the first real release run — post-tag (AC-07). | PENDING |
| AC-02 | A smoke failure on EITHER arch (`exit 1`: HTTP-off boot, per-slug route not `204`, or per-slug store assertion fails) fails the job and blocks the container release — the multi-arch manifest is not released. | grep + test | (config) `create-container-manifest.needs` includes both `smoke-amd64` and `smoke-arm64`; no `continue-on-error`/retry on smoke jobs. (behavioral, local) Run the smoke against a deliberately HTTP-off image → `exit 1`. (execution, post-tag) A red smoke leaves the manifest step skipped. | PENDING |
| AC-03 | A self-skip (`exit 3`, Docker absent) is a hard job failure with a clear diagnostic, never silent green. The gate additionally asserts the positive run-marker `[783-smoke] ALL GATES PASSED` was emitted, so an early-`exit 0` cannot masquerade as success. Green ⇔ smoke ran to its end and passed. | test | Stub-smoke unit test driving the gate's capture/`case`/grep logic: `exit 0` + anchored marker → green; `exit 1` (no marker) → red with "first-run path broken" `::error::`; `exit 3` → red with "mis-provisioned / hard failure" `::error::`; `exit 0` + marker absent (early-exit-0) → red with "exited 0 but never printed ALL GATES PASSED"; unexpected code → red. Only `(0, marker present)` is green. Truth table MUST exist before merge (R-01); RC propagation verified empirically, not by reading (R-02). | PENDING |
| AC-04 | Wiring introduces NO `needs` coupling between the container/smoke branch and the binary/npm branch. `build-linux-*`, `package-npm`, `create-release` are neither blocked by nor able to block the smoke. A smoke failure blocks only the container release path (the manifest). | grep | Trace the `needs:` graph in `release.yml`: no `smoke-*` job appears in any `build-linux-*`/`package-npm`/`create-release` `needs`; no binary/npm job appears in any `smoke-*` `needs`; `create-release` still `needs: package-npm` only. (ADR-004 #4572, R-06) | PENDING |
| AC-05 | The smoke additionally asserts the per-slug store GREW from the write AND the hash store did NOT receive it — pinning to the literal #783 symptom ("slug dir empty, hash dir populated"). One bounded change via the existing busybox sidecar; no `docker exec` into distroless. | test | (code review) The assertion pair is in `docker-http-posture-smoke.sh`, uses `vol()` read-only busybox inspection, samples a WAL-robust pre/post size signal, asserts per-slug grew + hash unchanged via `fail()`, placed before the terminal marker. (behavioral, local) Run the smoke end-to-end ≥5× → both assertions pass, signal monotone, `ALL GATES PASSED` still emitted last; negative-control: a hash-store mis-route would FAIL the assertion (R-04). | PENDING |
| AC-06 | The gate tests the actual shipped artifact — the GHCR-PUSHED per-arch tags. The resolved tag string is byte-identical to what `build-container-*` pushed: on a `v*` push the `v` is KEPT (`:v<version>-<arch>`, resolved UN-stripped from `${GITHUB_REF_NAME}`); on dispatch it is `:latest-<arch>`. This parity is provable PRE-MERGE so a tag-string VALUE mismatch is caught at merge, not at release. Self-build is rejected. No duplicate full image build. | grep + test | (config) Smoke jobs `docker login` to GHCR (`docker/login-action@v3`) and pass `IMAGE=ghcr.io/<owner>/unimatrix:<resolved-tag>-<arch>` where the push-path tag is resolved UN-stripped (`VERSION="${GITHUB_REF_NAME}"` ⇒ `:${VERSION}-<arch>`, **never** `${GITHUB_REF_NAME#v}`) and dispatch is `:latest-<arch>`; no production `docker build`/`buildx build` in the smoke jobs; `smoke-amd64 needs: [build-container-x64]`, `smoke-arm64 needs: [build-container-arm64]`. (pre-merge parity, FR-11) A static assertion in the gate-logic test surface proves the resolved tag is byte-identical to the metadata-action push pattern for both surfaces — `v1.2.3` ⇒ `:v1.2.3-<arch>` (matches `pattern=v{{version}}-<arch>`); a branch ⇒ `:latest-<arch>` (matches `value=latest-<arch>`) — RED at merge on any mismatch, no tag push required (R-09). (execution, post-tag) Smoke log shows "using prebuilt image: ghcr.io/...:v<version>-<arch>". | PENDING |
| AC-07 | The first real release run post-merge is watched to completion on the hosted runners (BOTH arches) and the gate is confirmed to actually run green. CI-dependent assertions are "configured + verified locally; GH execution confirmed post-tag," not asserted before execution. | manual | (process, post-tag) The delivery leader watches the first `v*` release run to completion; both `smoke-amd64` and `smoke-arm64` complete green; the manifest publishes; any platform/runner surprise (ARM64 flake, cold ONNX model-load timeout, tag-resolution mismatch) is treated as in-scope rework, never `|| retry`. Verifiable ONLY post-tag — cannot be proven by local Linux validation. | PENDING |
| AC-08 | On `workflow_dispatch`, the multi-arch manifest job is GATED OFF so only the `smoke-*` job statuses carry signal. The manifest job (which assembles `:${GITHUB_REF_NAME}` from per-arch tags the build does not push on a branch ref) does not run on dispatch and so cannot go falsely red. On a `v*` push the manifest job runs and stays smoke-gated (AC-02). | grep + manual | (config) `create-container-manifest` carries `if: github.event_name != 'workflow_dispatch'`; its `needs` still includes `smoke-amd64`/`smoke-arm64` for the push path. (behavioral, reasoned/local) On a dispatch ref the manifest job is green-skipped and the run's pass/fail reduces to the two smoke jobs; on a `v*` ref the manifest job runs gated by both smokes. (execution, post-tag/dispatch) A `workflow_dispatch` run shows the manifest job skipped and both smokes green. | PENDING |
