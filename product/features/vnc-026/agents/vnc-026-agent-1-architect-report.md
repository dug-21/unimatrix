## Key Decisions

1. **ADR-001 (SR-01)**: Parity corpus generated by a Rust dev-test from the live hook.rs
   as oracle; goldens committed under `packages/unimatrix/test/fixtures/parity/` with a
   CI regenerate-and-diff drift check (same pattern as ts-rs bindings, #4726). Full
   adversarial edge-case inventory enumerated. Doubles as F6 retirement evidence.
2. **ADR-002 (SR-02)**: Stdout host envelopes emitted from literal template strings
   (only the inner text scalar goes through JSON.stringify); goldens are the byte
   authority. Workspace serde_json has `preserve_order` (verified), so the Rust envelope
   key order is insertion order.
3. **ADR-003 (SR-05/SR-06/SR-03)**: Queue mini-spec — `~/.unimatrix/{hash}/hook-client/`,
   O_EXCL one-frame-per-file (lock-free), 500 files / 5 MiB / 24 h bounds with
   drop-oldest, replay bounded to 32 frames / 256 KiB per FNF spawn, atomic-rename
   offsets, 0600/0700 modes, session-key sanitization.
4. **ADR-004 (SR-06)**: transcript_delta frames are never written to disk. Failed delta
   = don't advance last_offset; next spawn re-derives the span from the transcript file
   (F2 merge idempotence makes re-ship free). Zero transcript bytes at rest client-side.
5. **ADR-005 (SR-10)**: Explicit observability trade-off — fail-open stays; content-free
   `health.json` breadcrumb (auth/connect/timeout classes, consecutive_failures,
   queue_depth) + stderr; init Ping is the only loud checkpoint; surfacing deferred to F5.
6. **ADR-006 (SR-09/RQ-3)**: Config = env vars (`UNIMATRIX_REMOTE_URL`/`_TOKEN`) over
   exactly one file location `{project_root}/.claude/settings.local.json`; root walk
   identical to state-dir derivation so config and state identity never diverge.
7. **ADR-007 (RQ-5)**: Separate second POST confirmed; refined to concurrent issuance
   (Promise.allSettled), independent outcome handling.

# Follow-Up Investigation: R-06 Elision-Hole Semantics vs MERGED F2 (PR #692)

## Task

Pin the elision-hole merge semantics from the merged vnc-025 F2 buffer code as-is;
determine what PreCompact serves for the elision gap and whether F2 rework (C-07) is
needed.

## Pinned Assertions

Evidence: `crates/unimatrix-server/src/infra/session_transcript.rs` (merged),
`crates/unimatrix-server/src/uds/listener.rs:1638-1663`,
`crates/unimatrix-server/src/uds/transcript_block.rs:380-395`.

### a. Merged apply_delta semantics for a client-elided delta

Under the originally spec'd shape (`offset = last_offset`, bytes = head+marker+tail,
~61,461 B for a span > 65,536 B):

- **At apply time: NO hole.** The write extends contiguously from the prior span end
  (Step 3, session_transcript.rs:147-153 — hole only when `write_offset > span_end`).
  `high_water = last_offset + bytes.length` (line 107) — **less than `file_len`**;
  server coverage and client `last_offset` disagree by `gap = N_elided − marker_len`.
- Tail bytes land at wrong logical offsets (`[last_offset + 49,152 + marker_len, end)`
  instead of true `[file_len − 12,288, file_len)`).
- Server `elided_bytes` unchanged — it counts only ring-tail/below-base drops (lines
  125, 132, 249, 267-269); client elision is invisible to it.
- **The NEXT delta (at `file_len`) creates the hole**: phantom hole
  `(last_offset + bytes.length, file_len)` pushed at lines 148-153, zero-filled,
  never fillable (elided bytes never re-sent, ADR-004). One permanent hole per
  elision; the 65th triggers `collapse_to_newest` (lines 28, 171-173, 311-326).

**Pinned fix (ADR-008): end-anchor the elided frame** — declared
`offset = file_len − bytes.length` so the frame ends exactly at `file_len`. Then
`holes == [(last_offset, file_len − bytes.length)]` forms eagerly BEHIND the content,
`high_water == file_len` (coverage agreement), the client tail lands at its TRUE file
offsets, and subsequent deltas extend contiguously — no further holes ever.

### b. PreCompact tail afterward

- `contiguous_tail` (session_transcript.rs:179-194) floors at the **last hole's end**.
  NUL/zero-fill is NEVER served under any frame shape (I4/FR-19 hold; vnc-025 ADR-002
  honored by the merged code).
- Span-start shape: once the post-elision delta arrives, the floor is `file_len` — the
  entire 61 KiB catch-up becomes permanently unservable; PreCompact serves only the
  (possibly tiny) post-elision content. **Starvation, not corruption.**
- End-anchored shape: floor is `file_len − bytes.length`; the full catch-up is
  servable immediately and later windows cross the seam contiguously.
- Marker in-band: the served window is 12,000 B (`MAX_PRECOMPACT_BYTES=3000 ×
  TAIL_MULTIPLIER=4`, listener.rs:1646) < the 12,288 B client tail, so the marker
  normally sits outside the window; if it enters one, the JSONL block builder
  (`extract_transcript_block_from_bytes`, transcript_block.rs:391-395) filters the
  non-parsing line(s) — the marker never reaches restoration block text.

### c. Client design compatibility

**NOT compatible as-is** with `offset = last_offset` (phantom hole + permanent
PreCompact starvation after every elision). **Compatible with a one-line geometry
change**: single frame retained (ADR-007 intact), bytes = head+marker+tail retained,
declared `offset = file_len − bytes.length`. The `last_offset` advance rule becomes
uniform: `declared offset + bytes.length` (= `file_len` for elided frames). Two-frame
true-offset alternative rejected (doubles POSTs, breaks ADR-007, loses the in-band
marker). Decision recorded as ADR-008.

### d. F2 rework (C-07)

**None required.** The merged buffer behaves exactly per its contract under both
shapes; the defect is purely client frame geometry, fixed client-side by ADR-008.
