# vnc-015 Acceptance Criteria Map

| AC-ID | Description | Verification Method | Verification Detail | Status |
|-------|-------------|---------------------|---------------------|--------|
| AC-01 | `context_store` accepts `edges: Option<Vec<{edge_type: String, target_id: u64}>>`. Omitting the parameter is identical to current behavior (backward compatible). | test | Integration: call without `edges`, compare response and DB state to baseline; call with `edges`, confirm GRAPH_EDGES rows written | PENDING |
| AC-02 | `context_correct` accepts the same `edges` parameter. Edges attach to the corrected (new) entry, not the deprecated original. | test | Integration: correct an entry with `edges`; confirm GRAPH_EDGES rows reference new entry id; confirm deprecated entry has no new outgoing edges | PENDING |
| AC-03 | All 10 new RelationType variants are defined in `graph.rs` with `as_str()` and `from_str()` arms: `Advances`, `Cites`, `Asserts`, `Mentions`, `Refutes`, `Tests`, `DerivedFrom`, `Motivates`, `About`, `RelatedTo`. | test | Unit test per variant: `from_str(v.as_str()) == Ok(v)` round-trip; grep verification of all 4 change sites per variant (10×4 checklist table) | PENDING |
| AC-04 | Existing 6 RelationType variants (`Supersedes`, `Contradicts`, `Supports`, `CoAccess`, `Prerequisite`, `Informs`) are unchanged. No regression in PPR, graph_expand, graph_penalty, or `build_typed_relation_graph`. | test | All existing graph-related tests pass without modification | PENDING |
| AC-05 | Each validated edge produces a GRAPH_EDGES row with correct `(source_id, target_id, relation_type)` triplet. `source = EDGE_SOURCE_AGENT`. `created_by = EDGE_SOURCE_AGENT` (`"agent"`). | test | Integration: store entry with edges; query GRAPH_EDGES; assert row field values | PENDING |
| AC-06 | For a `Contradicts` edge, both `(A, B, Contradicts)` and `(B, A, Contradicts)` rows are present in GRAPH_EDGES after the call. Both were written before the handler returned. | test | Integration: store entry with `Contradicts` edge to target B; query GRAPH_EDGES for both direction rows; assert both present | PENDING |
| AC-07 | Target validation: if any target_id does not reference an existing entry, the entire call fails (no entry written, no edges written). If any target_id references a quarantined entry, the call fails. Deprecated targets are allowed. | test | Integration (3 cases): (1) non-existent id → call fails, no DB writes; (2) quarantined entry id → call fails, no DB writes; (3) deprecated entry id → call succeeds, GRAPH_EDGES row written | PENDING |
| AC-08 | Self-referential edge rejection: if any edge has `source_id == target_id`, the entire call fails before entry insert. Clear error returned. Applies to `edges` param on `context_store`/`context_correct` and to `context_edge` (all modes). | test | Integration: `context_store` with `target_id` equal to actual auto-increment next ID (determined from pre-test insert); assert call fails, no entry inserted. Separate test for `context_edge`. | PENDING |
| AC-09 | Duplicate entries — no edge writes: if `insert_result.duplicate_of.is_some()`, no edges are written. Duplicate response is returned normally. | test | Integration: re-insert an existing entry with `edges`; confirm GRAPH_EDGES row count unchanged; confirm duplicate response returned | PENDING |
| AC-10 | INSERT OR IGNORE idempotency: re-asserting an identical `(source_id, target_id, relation_type)` triplet is a no-op — no error, no duplicate row. | test | Integration: write the same edge twice; query GRAPH_EDGES; assert exactly 1 row for that triplet; assert no error on second write | PENDING |
| AC-11 | `context_status` output includes `stale_dependency_edges: u64` counting `Prerequisite` edges whose source entry is Deprecated. | test | Integration: write Prerequisite edge; deprecate source; call `context_status`; assert `stale_dependency_edges >= 1` | PENDING |
| AC-12 | `context_cycle_review` emits a `DependencyOnDeprecated` finding (severity Warning, rule name `"dependency_on_deprecated"`) when a Prerequisite edge in the current cycle's entries points to a Deprecated source. | test | Integration: setup as AC-11; call `context_cycle_review`; assert finding present with correct rule name and severity | PENDING |
| AC-13 | `default_rules()` registers `DependencyOnDeprecated` as the 23rd rule. Test `test_default_rules_has_22_rules` updated to assert 23 rules. | test | Unit test: `default_rules(None, vec![]).len() == 23` | PENDING |
| AC-14 | All 10 new variant string forms survive `build_typed_relation_graph` Pass 2b without being silently dropped by the R-10 guard. | test | Integration per variant: insert a GRAPH_EDGES row with the variant string; call `build_typed_relation_graph`; assert edge count equals 1 (not 0) | PENDING |
| AC-15 | `Capability::Write` is required for `context_store`, `context_correct`, and `context_edge`. Unenrolled or read-only agents receive the existing permission error. No new capability introduced. | test | Existing capability gate tests cover `context_store`/`context_correct` implicitly. New test: `context_edge` rejects agent without `Capability::Write` | PENDING |
| AC-16 | `query_contradicts_edges_for_entry` in `read.rs` uses a bidirectional query (both `source_id = ?1` and `target_id = ?1` covered via OR clause). All existing callers verified to handle both directions. | test | Integration: write `Contradicts` edge A→B (bidirectional); call `query_contradicts_edges_for_entry(A)` and `query_contradicts_edges_for_entry(B)`; assert both return the edge | PENDING |
| AC-17 | `RelatedTo` appears in `positive_out_degree_weight` (`graph_ppr.rs`) and the positive BFS set (`graph_expand.rs`). PPR mass flows through `RelatedTo` edges. `Advances` and `Motivates` are NOT added to PPR in this feature (write-only, deferred to Phase 2). | test | Unit test: build TypedRelationGraph with `RelatedTo` edge; run PPR; assert both endpoints surface. Negative test: write `Advances`/`Motivates` edges; confirm PPR scoring unchanged from baseline (no mass flow through these types). | PENDING |
| AC-18 | Agent-declared edges use `EDGE_SOURCE_AGENT` constant (`"agent"`) in `source` column. The `&None` session_id in `context_correct` does not block the write path. | test | Integration: store entry with edges via enrolled agent; query GRAPH_EDGES; assert `source` matches `EDGE_SOURCE_AGENT`; assert `created_by` matches `EDGE_SOURCE_AGENT` | PENDING |
| AC-19 | `context_edge` MCP tool exists as the 13th tool with parameters `mode: "add"|"remove"|"redirect"`, `source_id: u64`, `edge_type: String`, `target_id: u64`, `new_target_id: Option<u64>` (required for redirect, rejected for add/remove). | test | Tool registration test confirms 13 tools. Schema inspection confirms parameter types. Integration: submit add/remove/redirect calls and confirm correct behavior for each. | PENDING |
| AC-20 | `context_edge` is a pure graph operation: no embedding recompute, no confidence update, no duplicate detection triggered under any mode. | test | Integration: call `context_edge(mode: "add")`; confirm no embedding job queued, no confidence delta, no duplicate detection log entry | PENDING |
| AC-21 | `context_edge` requires `Capability::Write`. Unenrolled or read-only agents calling `context_edge` receive the existing permission error. | test | Integration: call `context_edge` with agent missing `Capability::Write`; assert permission error returned | PENDING |
| AC-22 | No ownership check on `context_edge`. Any `Capability::Write` agent may operate on any non-frozen source entry regardless of who created it. `agent_id` is not a reliable ownership anchor in this RBAC model. | test | Integration: enroll agents A and B; A stores entry; B (with Capability::Write) calls `context_edge` on A's entry; assert success (no OwnershipViolation, no error). | PENDING |
| AC-23 | `context_edge` rejects operations where the source entry is quarantined or deprecated. `SourceFrozen` error returned. | test | Integration: quarantine an entry; call `context_edge` on it; assert `SourceFrozen`. Repeat for deprecated entry. | PENDING |
| AC-24 | `context_edge(mode: "add")` writes the edge row. Idempotent on re-assertion (INSERT OR IGNORE). Target validation applies: non-existent target fails (`TargetNotFound`), quarantined target fails (`TargetQuarantined`), deprecated target succeeds. | test | Integration: add edge to valid target (confirm row); add to non-existent id (confirm `TargetNotFound`); add to quarantined entry (confirm `TargetQuarantined`); add to deprecated entry (confirm success); re-assert same edge (confirm no error, no duplicate row) | PENDING |
| AC-25 | `context_edge(mode: "remove")` deletes the `(source_id, target_id, relation_type)` row. For `Contradicts`, both `(A, B)` and `(B, A)` are deleted atomically. Returns success even if the edge does not exist (idempotent). | test | Integration: add a `Contradicts` edge; remove it; confirm both direction rows deleted. Call remove again; confirm success (idempotent). Confirm non-Contradicts remove deletes only the specified row. | PENDING |
| AC-26 | `context_edge(mode: "redirect")` atomically removes the old `(source_id, target_id)` edge and inserts `(source_id, new_target_id)`. For `Contradicts`, all four direction rows managed atomically via RAII transaction (`pool.begin()`). New target validated per AC-07. If redirect fails mid-transaction, original rows are restored (ROLLBACK). | test | Integration: add A→B; redirect to B'; confirm A→B deleted AND A→B' present. For Contradicts: add A↔B; redirect to B'; confirm all 4 rows updated atomically. Redirect to non-existent id; confirm `TargetNotFound`, original rows unchanged. | PENDING |
