## Design Review (uni-architect) — APPROVED WITH NOTES

### Answers to the four questions
**(a) Is remote.json a reliable marker?** Yes. vnc-039 ADR-003 (#5126) fixes the layout as `~/.unimatrix/<projectHash>/remote.json`, one file per hash dir. All three sites are on the remote-attach path (Gate 6, Gate 8 cloud cycle, Gate 9 client-works), and none runs on the UDS leg (the `daemon_server` fixture never reads it). Each site already fails when `[ -f "$cred_file" ]` is false, so the marker adds no new failure mode. The nan-024 layout is `bin/`, `pkg/<ver>/` and `install.json`, so nothing else can match `-mindepth 2 -maxdepth 2 -type f -name remote.json`. A stray hash dir without a cred, such as hook state under a different realpath hash, was a false failure under the old count and is now correctly ignored. A legitimate second `remote.json` would need a second attached project, which the hermetic `$SANDBOX/home` never has. The exactly-1 check stays meaningful.
**(b) Does the UDS wait need a handshaken call?** `client.py:334` makes **no tool call**. It scans server stderr for `embedding model loaded` (`embed_handle.rs:148,150`; the retry variant also matches). `UnimatrixUdsClient` does not own the daemon process, so a client-side `wait_until_ready` would have to probe with a tool call. That probe would add query/usage rows on the UDS leg only, an asymmetric write against the field-for-field parity contract (nan-021 ADR-003 #5293). **Revise F2** (see N1).
**(c) ADR conflict / H3?** None. The fix is consistent with #5126, nan-019 ADR-003 #5183 (the exit 0/1/3 + run-marker contract is unchanged; every miss is still `fail()` → exit 1), and nan-021 ADR-002 #5294 (the "credstore present" gate is kept). No nan-024 ADR (#5900/#5945/#5948/#5956) claims exclusive ownership of the `~/.unimatrix` top level. No new ADR is needed.
**(d) Release/ci route?** The fix touches only `product/test/infra-001/**`. It needs no `release.yml` or `ci.yml` edit, and `/uni-release` is needed only to cut v0.12.1. PR-CI gating stays a separate issue (ci.yml changes go via issue).
